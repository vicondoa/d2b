| [0053. Separately excludes d2b from the execution path, because contributor tooling must not consume the framework it is used to develop, and proves that by configuration scan, execution trace, and controlled denial with d2b running normally rather than by requiring d2bd to be stopped. Execution is the upstream-supported local model, `tmux` sessions in per-task host git worktrees. The `gc` binary comes from the `gascity` package of `numtide/llm-agents.nix` (measured at main `7b99fc4bbb8a7c2fff82c2708d8636c1cbc65661`, Gas City 1.4.0, wrapping `gc` with its own runtime PATH closure); that flake exposes packages and an overlay but no NixOS module, and no reusable Gas City module was found to adopt, so deployment splits four ways: `llm-agents.nix` for the package; a new `vicondoa/gascity.nix` for the generic reusable NixOS module owning systemd units and ordering, the five principals, state and lock paths, ordered shutdown and restart adoption, dashboard read-only enforcement, worker namespace and firewall primitives, the append and audit helper, rotation and retention, health checks and module tests, carrying nothing d2b-specific at all (no d2b identifier, path, option, default, workflow or assumption) under a `services.gascity` option namespace, with a mechanical scan proving the absence of any d2b identifier or dependency rather than leaving it to review; `vicondoa/d2b-gascity-configs` for d2b policy including city.toml, packs.lock, formulas, rig binding, the single Discord identity, the d2b egress allowlist, approval policy and importer; and `/etc/nixos` for machine-private instantiation. Neither `llm-agents.nix` nor `gascity.nix` is ever a d2b flake input, and this record authorizes creating the two repositories later rather than creating them now. Versions are a three-way pin across the configuration revision, the `llm-agents.nix` revision, and `packs.lock`, with `gascity_compat` checked against what the deployed binary reports from `gc version` and upgrade or rollback being a deliberate lock change. Treats local agent processes as untrusted principals even though the deployment is single-user, and splits the host into five principals with distinct Unix identities: an orchestrator owning durable state and a protected integration Git object store, an agent-worker running sessions in isolated worktrees and its own default-deny network namespace with no route to d2b bridges, the LAN, link-local addresses or host loopback, an approval controller that verifies Discord signatures plus the allowlist and derives the artifact identity and operator prompt from the immutable commit rather than from worker-supplied text, a publisher that alone holds the repository-scoped GitHub credential and accepts only an immutable commit hash after verifying the approval node, decision and hash, and a root-owned append helper that is the only writer of write-once approval and audit records, admitting exactly three peer-credential-checked caller-and-kind pairs (approval controller with approval, publisher with publication-attempt, root retention timer with retention-deletion) and deriving every record name itself so no caller supplies a path. The store is a periods directory of UTC-dated period directories plus a sibling quarantine directory on one filesystem; callers submit typed deny-unknown fields rather than bytes and the helper builds the canonical envelope, embeds the peer-authenticated kind, hashes its own bytes and derives a kind-bound name so no caller can store a record of a kind it does not own; appends install atomically through a same-directory temporary, file fsync, a required renameat2 RENAME_NOREPLACE with no linkat or copy fallback, and a period-directory fsync before acknowledgement, with a post-fsync crash retried as verified idempotent success that re-fsyncs before returning, abandoned temporaries always unlinked and budgeted, and a digest mismatch failing closed as corruption that is never resolved by deleting history. The helper holds a single-owner store lock for its lifetime, does no cleanup before adopting it, and reconciles temporaries individually; sealed periods carry a manifest so a physically missing record is detectable by a read-only verify command. Retention removes only whole sealed periods by renaming into quarantine, fsyncing both the periods and quarantine directories, recording the deletion, and only then deleting contents, so a crash leaves a period wholly present or wholly quarantined and never partially deleted; a failed audit append retains the quarantine and raises a closed retention-audit-append-failed error with a named operator status command rather than surfacing weeks later as a disk cap. Durable records carry keyed digests of Discord ids and run handles rather than plaintext, rotate daily under bounded retention, and every publication attempt emits exactly one bounded redacted audit record. Both separations are required, because withholding the credential alone is defeated by an agent forging the approval and invoking the publisher legitimately; and no boundary may be asserted within a single uid, including by systemd per-unit credentials, which isolate a secret from other uids but not from a peer process sharing the same one. Absence scans must assert counted non-empty coverage and reject planted violations. Keeps the standalone skills first-class and independently verifiable rather than byte-frozen, has Gas City orchestrate the panel stage while review and attestation stay with the unchanged d2b panel tooling and the bridge between them stays unproven and prototype-gated, makes approvals bound to an artifact content hash and fail closed on mismatch, and requires a named pre-change failure proof and post-change validation for tasks where a unit test is not meaningful. Scopes the deployment to one operator on one machine: Discord ingress is allowlisted fail-closed to a single configured user id and optional guild/channel and rejected at ingress before touching workflow state, the approval reviewer is that one operator, and the dashboard runs in upstream read-only mode bound to loopback, because loopback excludes remote humans but admits every local agent and the upstream respond path would let an agent answer its own permission prompts. No multi-user RBAC, tenancy, HA, or remote access is designed. That single-user scope is explicitly not a reason to merge identities or relax the dashboard, because the boundary is operator versus agent process rather than one human versus many. |
