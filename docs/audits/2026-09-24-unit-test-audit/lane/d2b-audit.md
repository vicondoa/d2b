## Findings (biggest net first)
- duplicate: `garbage_checkpoint_scratch_without_commit_is_discarded` (src/segment.rs:1379) - covered by `truncated_checkpoint_scratch_is_discarded_before_recovery` (src/segment.rs:1362). Both pin: an unparseable `audit-checkpoint.json.next` scratch file is discarded on open and recovery proceeds with the genesis anchor; the only setup difference is whether a committed checkpoint file exists, which does not change the pinned behavior.
- duplicate: `impossible_success_is_integrity_failure_and_one_sided_terminal_is_not_replayed` (src/reconcile.rs:177) - covered by `matching_success_requires_both_durable_domains` (src/reconcile.rs:144) and `missing_or_mismatched_domains_fail_closed` (src/reconcile.rs:159). Both halves re-pin the same `reconcile()` branches: a Success with a non-durable effect is IntegrityFailure (test 1 pins the asymmetric case, this one the symmetric - same `||` predicate), and a one-sided terminal evidence is IntegrityFailure (test 2 pins it with Success outcome, this one with Failure - same branch; only Pending is special-cased).
- duplicate: `the_root_invocation_id_survives_every_hop` (src/evidence_chain.rs:278) - covered by `a_nested_call_appends_the_invoking_identity_and_never_re_roots` (src/evidence_chain.rs:255). Both pin: `EvidenceChain::nested()` preserves the root invocation id and increments depth per hop; the covering test pins strictly more (initiating identity never re-roots, invoking identity = last hop, ordered identity list), the deleted one only loops more hops.
- gap: `evidence_from_decision_result` valid closed pairs (allowed/success, denied/denied, error/error → typed outcomes) and `reconcile()` Pending → ReplayRequired transitions (both-pending and one-sided-pending) have no test - src/reconcile.rs:191 only pins the rejection paths. The success/denied/error parse table is the function's whole purpose.
- gap: `AuditSink::append` non-privileged outcomes - Standard/BestEffort → `RateLimited` and append-failure → `DroppedUnavailable` are never exercised (all sink tests use Privileged; src/sink.rs:145-190). The limiter itself is tested in rate_limit.rs but the sink's class→outcome mapping is not.
- gap: export bounds - `MAX_EXPORT_RECORDS`/`MAX_EXPORT_BYTES`/`MAX_EXPORT_SCAN_LINES`/`MAX_EXPORT_SCAN_BYTES`/`MAX_EXPORT_DIRECTORY_ENTRIES` limits and `after`/`before` range filtering (src/export.rs:56-140) have no test; the single export test only pins the inline hash-break line.
