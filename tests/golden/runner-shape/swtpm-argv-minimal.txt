# (the audit_swtpm_input_parity_golden test panics with the observed vs expected diff).
# Plan: ph1-p1-swtpm-persistence - the long-lived swtpm sidecar argv shape is locked here.
# No `--daemon` entry: swtpm socket is foreground by default and `--daemon` takes no
# argument, so the pre-0.10 `--daemon=false` spelling the installed swtpm rejects is gone.
# No `uid=`/`gid=` owner entry: a launch no longer carries a caller-chosen
# numerical broker identity. swtpm chowns each socket to the id it is given, and
# inside the launch's user namespace that chown is refused - "Could not change
# ownership of UnixIO socket to 0:0 Operation not permitted" - so swtpm exits 1
# before it binds the data socket, leaving no log, no pid file and no NVRAM. Each
# socket is therefore created owned by the uid swtpm itself runs as, which is what
# `mode=0660` and the state directory's ACL are written against.
# No free-form argument tail either: every filesystem input below comes from the
# worker's admitted state binding, and an argument naming a device node is refused.
