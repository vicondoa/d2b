# d2b_provider_device_tpm::swtpm_argv::generate_swtpm_argv(audit_swtpm_input())
# Format: argv joined by '\n', one argument per line. Update via
# `cargo test -p d2b-provider-device-tpm --lib swtpm_argv`
# (the audit_swtpm_input_parity_golden test panics with the observed vs expected diff).
# Plan: ph1-p1-swtpm-persistence - the long-lived swtpm sidecar argv shape is locked here.
# No `--daemon` entry: swtpm socket is foreground by default and `--daemon` takes no
# argument, so the pre-0.10 `--daemon=false` spelling the installed swtpm rejects is gone.
# The `uid=`/`gid=` owner entries are opt-in (`SwtpmArgvInput::uid/gid`), and
# this golden exercises them. The namespaced device-worker launch passes
# `None`: swtpm chowns each socket to the id it is given, and inside that
# launch's user namespace the chown is refused - "Could not change ownership of
# UnixIO socket to 0:0 Operation not permitted" - so swtpm exits 1 before it
# binds the data socket, leaving no log, no pid file and no NVRAM. Omitting the
# entries leaves the socket owned by the uid swtpm itself runs as.

--server
